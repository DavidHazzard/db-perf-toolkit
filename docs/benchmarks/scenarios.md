## Small

One `orders` table with the everyday problems: a few unused indexes covering each refusal category, dead tuples, and a sequential-scan hotspot. This is the shape most application databases are actually in.

## Realistic

Four whale tables, sixteen mid-size, and a long tail of 180 small ones — the distribution real databases have. Index hygiene that nobody revisited: redundant prefixes, an exact duplicate under a different name, unique indexes nobody queries.

## Horror

Ten years of decisions nobody was around to defend, in four strata:

| Era | What it left behind |
|---|---|
| College project | Everything `text`, including dates and money. No constraints. Tables named `data`, `temp`, `test1`. |
| Startup | Partitioning by copy-paste — a table per year. Indexes added during 3am outages, never removed. |
| PE acquisition | Audit tables duplicating everything. Soft deletes, so nothing is ever really deleted. |
| Offshore rewrite | An index on every column including four booleans. Backup tables. `users_final_v2_new`. |

It also carries the identifiers that break naive tooling: `"Mixed.Case.Index"`, `"index'with'quotes"`, and a table named `"user data old"`.

Result: **2,017 indexes across 202 tables**, 90% of them unread.
